# Leo Wingman 架构设计 - 真正懂你的僚机系统

> 设计理念：不是代码堆成山，而是越用越懂你的智能伙伴
> 目标用户：房地产/商业地产营销从业者

---

## 一、现状问题诊断

### 你现在面对的

```
❌ 人工智障现状：
- 你说"转PDF" → 给你10个文件 + 一堆脚本 + 还要你管HTML/幻灯片
- 每次新任务都要从头解释背景
- 系统越来越复杂，文件越来越多
- 你需要记得各种命令、路径、配置

❌ 代码堆成山：
- src/leo_skills/ 下面230+个技能，大多数是僵尸
- 各种evolution.json、config.yaml、SKILL.md
- 脚本分布在 scripts/development/ scripts/business/ scripts/maintenance/
- 连我都需要查文档才知道该用哪个
```

### 你真正想要的

```
✅ 僚机模式：
- 你说"把这个给分销团队" → 系统自动选格式、排版、发送
- 系统记得：你是卖商铺的、目标客群是投资客、常用话术风格
- 越来越省事：第一次说详细点，后面只说"按上次那样"
- 你专注业务，系统自己进化
```

## 二、核心设计原则

### 2.1 三零原则

| 原则 | 含义 | 例子 |
|------|------|------|
| **零配置** | 不需要手动改配置文件 | 系统自动检测环境、自适应参数 |
| **零记忆负担** | 不需要记命令和路径 | 自然语言交互，系统记住上下文 |
| **零维护** | 不需要管系统健康 | 自诊断、自修复、自优化 |

### 2.2 僚机三能力

```
1. 察言观色（感知）
   - 你在看什么文件 → 猜测你在准备什么
   - 你经常修改哪类内容 → 记住你的风格
   - 上次成功的方法 → 下次优先用

2. 主动服务（预判）
   - 每周一早上 → 自动准备周报模板
   - 新项目启动 → 自动复制上次的成功套路
   - 检测到你在重复操作 → 主动说"这个我可以自动做"

3. 端到端交付（执行）
   - 不是生成文档就完事
   - 而是：生成 → 排版 → 转格式 → 发到飞书/微信 → 通知相关人员
```

## 四、端到端执行系统（帮你办完）

### 4.1 任务理解引擎

**传统方式：**
```
你："转PDF"
系统：给你一堆文件，你自己处理
```

**僚机方式：**
```
你："把这个发给分销团队"
系统理解：
  - "这个" → 当前编辑的文件
  - "分销团队" → 需要PDF格式（便于转发）+ 微信话术（便于复制）
  - "发" → 生成后直接上传到飞书指定文件夹

系统执行：
  1. 自动排版（适合手机查看）
  2. 生成PDF + 提取关键话术
  3. 上传到飞书「分销资料」文件夹
  4. @分销群："新资料已更新"
  5. 告诉你："已发送，本周下载量23次"
```

## 五、系统自管理（不用你操心）

### 5.1 技能生命周期自动管理

**传统：**
- 创建skill → 写SKILL.md → 配config → 写进化文件 → 手动测试

**僚机：**
```
你："帮我做个自动跟客户的功能"
系统自动：
  1. 分析需求 → 确定是"客户跟进提醒"
  2. 检查已有技能 → 发现类似功能
  3. 复用+改造 → 生成新功能
  4. 自动测试 → 验证可用
  5. 静默部署 → 不打扰你
  6. 观察使用 → 自动优化

不需要你管文件放哪、怎么命名、怎么配置
```

### 5.2 自动清理与合并

```python
class SystemSelfCare:
    def daily_cleanup(self):
        """
        每天自动维护系统
        """
        # 清理过期文件
        delete_temp_files_older_than(days=7)

        # 合并重复技能
        if detect_duplicate_skills():
            suggest_merge()

        # 归档僵尸技能
        if skill_unused_for(days=90):
            archive_to_cold_storage()

        # 优化存储
        compress_old_outputs()
```

### 5.3 无感进化

```
你："这个PDF字体还是小了"

系统后台动作（你看不到）：
  1. 记录反馈到用户画像
  2. 自动调整参数：font_size += 2
  3. 重新生成你最近的项目文档
  4. 对比新旧效果
  5. 确认改善 → 永久保存参数
  6. 告诉你："已调整，你看看"

不需要你：
  - 找CSS文件
  - 改配置
  - 重新运行脚本
  - 检查输出
```

```

├── memory/              # 用户画像 + 上下文记忆

│
└── selfcare/            # 系统自维护

    ├── optimizer.py         # 自动优化

```

### 7.2 交互接口（唯一入口）

**不需要记住：**
- 各种脚本路径
- 配置文件位置
- 命令行参数

```
自然语言 → 系统理解 → 自动执行 → 结果交付

```

```

1. 建立时间触发器（周一周报、活动前准备）

3. 自动推荐下一步（基于成功案例）

- 系统提醒："分销团队3天没新素材了，要做一个吗？"
```

### Phase 4：自进化（持续）

```
目标：越用越顺手，你感受不到系统的存在

动作：
1. 每次交互都优化用户画像
2. 自动测试新策略，保留有效的
3. 清理用不到的功能

交付：
- 3个月后，系统比你更清楚你通常要什么
- 80%的操作只需要你说3个字
```
