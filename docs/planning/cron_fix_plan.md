
## 二、修复方案

### 2.1 短期修复（立即执行，1 小时）

#### 方案 A: 分散推送时间
将 17 个 8:00 任务分散到不同时间段，避免资源竞争：

| 时间段 | 任务数量 | 任务类型 |
|--------|----------|----------|
| 07:30 | 2 个 | 系统类（能力索引、健康检查） |
| 08:00 | 5 个 | 核心资讯（房产、AI 财经、OpenClaw） |
| 08:30 | 5 个 | 内容策略（别墅、创意、监控） |
| 09:00 | 5 个 | 补充报告（抖音、小红书、AI 报告） |

#### 方案 B: 添加请求间隔
为每个任务添加 `staggerMs` 配置，错开执行时间：

```json
{
  "schedule": {
    "expr": "0 8 * * *",
    "tz": "Asia/Shanghai",
    "staggerMs": 60000  // 每个任务间隔 60 秒
  }
}
```

#### 方案 C: 优化 Prompt
修改触发内容审核的 Prompt，移除敏感词：

**原 Prompt**: "搜索...国际政治 10 条"
**新 Prompt**: "搜索...商业财经 10 条 + 科技动态 10 条"

### 2.2 中期修复（本周内，2-4 小时）

#### 任务 1: 添加重试机制
```python
# 在 cron 配置中添加
"retry": {
  "maxAttempts": 3,
  "delayMs": 5000,
  "backoff": "exponential"
}
```

#### 任务 2: 消息长度限制
所有推送消息限制在 2000 字以内，超出部分：
- 方案 A: 拆分为多条消息
- 方案 B: 生成飞书文档链接

#### 任务 3: 错误通知优化
失败时发送详细错误报告，包括：
- 失败任务名
- 错误类型
- 建议操作

### 2.3 长期优化（下周）

1. **迁移搜索服务**: Brave → 多服务商负载均衡
2. **添加监控看板**: 实时显示任务执行状态
3. **实现熔断机制**: 连续失败 3 次自动暂停任务
