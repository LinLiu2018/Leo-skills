# Prompt Optimizer - 提示词优化器

## 功能描述

这个技能帮助你优化任何提示词,使其更加清晰、明确和有效。基于 Claude 官方提示词工程最佳实践,自动分析并改进你的提示词。

## 使用场景

- 优化现有提示词以获得更好的输出
- 将模糊的需求转化为清晰的提示词
- 为复杂任务创建结构化提示词
- 改进提示词的格式和组织

## 使用方法

当用户请求优化提示词时,按照以下步骤操作:

### 1. 分析原始提示词

首先分析用户提供的提示词,识别以下问题:

- ❌ 指令不够明确
- ❌ 缺乏上下文和动机
- ❌ 过于模糊,缺少具体约束
- ❌ 缺少示例
- ❌ 没有允许表达不确定性
- ❌ 结构混乱

### 2. 应用优化技巧

根据以下核心原则优化提示词:

#### 明确性 (Explicitness)

- 使用直接的动作动词开头:"写"、"分析"、"生成"、"创建"
- 跳过铺垫,直奔主题
- 明确说明输出应包含什么
- 具体说明质量和深度期望

#### 上下文 (Context)

- 解释为什么这个任务重要
- 说明受众是谁
- 描述输出将如何使用
- 指明要解决的问题

#### 具体性 (Specificity)

- 添加明确的约束(字数、格式、时间线)
- 提供相关上下文(受众、目标)
- 指定期望的输出结构(表格、列表、段落)
- 列出任何要求或限制

#### 示例 (Examples)

- 当格式难以描述时提供示例
- 展示期望的语气或风格
- 使用 one-shot 或 few-shot 方法

#### 结构化 (Structure)

- 使用 XML 标签或 Markdown 标题组织内容
- 将不同部分清晰分隔
- 对长文本使用 `<document>`, `<context>`, `<instructions>` 等标签

### 3. 输出优化后的提示词

提供以下内容:

1. **分析报告**: 简要说明原提示词的问题
2. **优化后的提示词**: 完整的改进版本
3. **改进说明**: 解释做了哪些关键改进
4. **使用建议**: 如何进一步调整以适应特定需求

## 优化模板

使用以下结构作为优化参考:

```
<context>
[解释任务背景、目标受众、使用场景]
</context>

<instructions>
[清晰、明确的指令,使用动作动词]

要求:
- [具体约束 1]
- [具体约束 2]
- [具体约束 3]

输出格式: [明确的格式要求]
</instructions>

<examples>
[如果需要,提供 1-2 个示例]
</examples>

<guidelines>
- 如果信息不足以完成任务,请说明而不是猜测
- [其他相关指导原则]
</guidelines>
```

## 高级技巧

### 对于复杂任务

- 考虑使用思维链 (Chain of Thought)
- 添加 `<thinking>` 标签让 AI 先思考再回答
- 将复杂任务分解为多个步骤

### 对于长文本处理

- 将长文本数据放在提示词顶部
- 使用 XML 标签结构化多个文档
- 要求 AI 先引用相关部分再回答

### 对于格式控制

- 使用预填充 (prefill) 技术
- 明确说明要做什么,而不是不要做什么
- 提供格式示例

## 示例

### 原始提示词

```
帮我写一篇关于 AI 的文章
```

### 优化后的提示词

```
<context>
我需要为科技博客撰写一篇面向普通读者的文章,介绍 AI 在日常生活中的应用。
目标受众是对技术感兴趣但没有专业背景的普通读者。
</context>

<instructions>
撰写一篇关于 AI 在日常生活中应用的科普文章。

要求:
- 字数: 800-1000 字
- 语气: 通俗易懂,避免专业术语,如需使用请解释
- 结构: 引言 + 3-4 个具体应用场景 + 总结
- 每个应用场景包含: 场景描述、技术原理(简化版)、实际例子

输出格式: 使用 Markdown 格式,包含标题和小标题
</instructions>

<guidelines>
- 使用生活化的例子,让读者容易理解
- 避免过度技术化,保持文章的可读性
- 如果某个应用场景的信息不够准确,请说明而不是编造
</guidelines>
```

## 注意事项

1. **不要过度优化**: 保持提示词简洁,只添加必要的信息
2. **考虑模型版本**: Claude 4.x 对明确性和示例细节更敏感
3. **迭代改进**: 根据输出结果继续调整提示词
4. **保持灵活性**: 为 AI 留出一定的创造空间
